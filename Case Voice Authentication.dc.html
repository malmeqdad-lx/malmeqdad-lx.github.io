Pharmaceutical · Employee support IVR

The caller is already annoyed. Now authenticate them.

Nobody calls a support line to enjoy it. By the time authentication starts, the caller has already navigated a phone tree and is holding a case number they can't read out loud. This flow had two jobs: verify identity, and spend as few of the caller's turns doing it as possible.

Role

Conversation designer. Call flow, prompt writing, error and escalation strategy.

Scope

Authentication, intent collection, and case status lookup, feeding HR, payroll and procurement queues.

Channel note

Voice. No buttons to fall back on, no scrollback, and every prompt costs the caller real seconds.

The rule

Most IVRs have one fallback for the whole call. Ask anything, misunderstand anything, get the same apology. It's cheap to build and it teaches the caller that the system isn't listening, because the response to 4-1-5 is identical to the response to silence.

Here, every prompt that takes input owns its own error prompt, its own retry wording, and its own exit. Two failures at any single capture point ends the loop and hands the caller to a person, tagged with why. Callers who fail authentication are then allowed straight through to an agent on their next attempt, so the system can't bounce them between authentication and transfer forever.

Three habits

Escalate the wording, not just the counter

First retry admits a partial hearing and re-asks specifically. Second admits defeat plainly and stops. Repeating the same apology twice is how a caller learns to say agent.

Every transfer carries a reason

Auth failure, explicit agent request, unsupported intent. Without the tag, the monthly report says containment dropped and nobody can say which prompt caused it.

Ask for what the caller already has

The inbound number is checked before a single question is asked. When it matches, authentication costs one prompt instead of three, and the majority of callers never see the rest of this diagram.
